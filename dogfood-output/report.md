## Правила фиксации

- Функциональную ошибку проверяем повторно перед включением в отчёт.
- Для каждого дефекта указываем шаги, ожидаемый и фактический результат, адрес страницы и доказательство.

## Дефекты

### ISSUE-001: Ошибка в подсказке выбора доставки

| Поле | Значение |
|---|---|
| Критичность | Низкая |
| Категория | Контент |
| Адрес | `/dk/checkout?step=delivery` |
| Видео | Не требуется: ошибка видна при загрузке |

**Ожидалось:** грамматически корректная подсказка о выборе способа доставки.

**Фактически:** показано «How would you like you order delivered» вместо «How would you like your order delivered?». Ошибка видна при каждом открытии шага Delivery.

**Воспроизведение:** добавить товар в корзину, заполнить адрес доставки и перейти к шагу Delivery. [Снимок экрана](screenshots/issue-001-delivery-copy.png).

### ISSUE-002: На шаге Review вместо условий ручной оплаты показан текст-заглушка

| Поле | Значение |
|---|---|
| Критичность | Средняя |

| Адрес | `/dk/checkout?step=review` |

### ISSUE-003: На шаге Review нельзя открыть документы, принятие которых требуется от покупателя

| Поле | Значение |
|---|---|
| Критичность | Средняя |

| Адрес | `/dk/checkout?step=review` |
| Видео | Не требуется: ошибка видна при загрузке |

**Ожидалось:** названия Terms of Use, Terms of Sale, Returns Policy и Privacy Policy ведут к соответствующим документам либо рядом есть явная ссылка для их просмотра.

### ISSUE-004: Покупателю сообщается об оплате, хотя заказ не оплачен

| Поле | Значение |
|---|---|
| Критичность | Высокая |
| Категория | Функциональность / согласованность статусов |
| Адрес | `/dk/order/order_01M3KVHCAV00GXJB1NNTAZ4PGB/confirmed` и `/app/orders/order_01M3KVHCAV00GXJB1NNTAZ4PGB` |
| Видео | Недоступно: запуск записи отклонён политикой среды; приложены снимки обеих сторон |

**Ожидалось:** подтверждение заказа показывает фактический статус Manual Payment и не утверждает, что сумма уже уплачена, пока в заказе оплачено €0.

**Фактически:** покупателю на странице подтверждения заказа №15 показано «€30.00 paid at …». В админке тот же заказ имеет Paid Total €0, Outstanding amount €30, payment Pending и кнопку Capture payment. Повторное открытие страницы подтверждения сохраняет расхождение.

**Воспроизведение:**

1. Оформить заказ с Manual Payment на €30 и открыть страницу подтверждения. [Снимок покупателя](screenshots/issue-004-customer-paid.png).
2. Открыть этот же заказ №15 в админке и прокрутить до Payments. [Снимок админки](screenshots/issue-004-admin-payment-details.png).

### ISSUE-005: Десятичная точка в цене превращает €5.00 в €500.00

| Поле | Значение |
|---|---|
| Критичность | Высокая |
| Категория | Функциональность / ввод цены |
| Адрес | `/app/products/prod_01M3KVZF7B6GHT2QQTY14R9R2Q/variants/...` (диалог редактирования Prices) |
| Видео | Недоступно: запись отклонена политикой среды; приложены снимки до и после ввода |

**Ожидалось:** ввод `5.00` в Price EUR сохраняет €5.00 либо отклоняется с понятной подсказкой о требуемом разделителе.

**Фактически:** точка без предупреждения удаляется. После потери фокуса поле показывает `500,00`; при публикации тестового товара из введённого `5.00` сохранилась цена €500.00. Ввод `5,00` даёт корректные €5.00. Ошибка повторена в диалоге редактирования цены; неверное изменение отменено, у тестового товара сейчас €5.00.

**Воспроизведение:** открыть Prices для варианта, [исходное значение €5.00](screenshots/issue-005-price-before.png); заменить на `5.00` и перевести фокус с поля — [получится €500.00](screenshots/issue-005-price-after.png).

### ISSUE-006: Загрузка изображения товара завершается ошибкой

| Поле | Значение |
|---|---|
| Критичность | Высокая |
| Категория | Функциональность / медиа товара |
| Адрес | `/app/products/prod_01M3KVZF7B6GHT2QQTY14R9R2Q` → Media |
| Видео | Недоступно: запись отклонена политикой среды; приложен снимок ошибки |

**Ожидалось:** после выбора изображения допустимого формата PNG/JPEG и нажатия Save оно сохраняется в Media товара.

**Фактически:** оба формата не удалось загрузить. Форма показывает «Failed to upload the added media. Please try again.», миниатюра остаётся сломанной, сервер возвращает «Invalid request: Field 'images, 0, url' is required». В журнале сети после POST `/admin/uploads` следует POST товара с ответом 400. Повторено на PNG 600×600 и JPEG 128×128. [Снимок ошибки](screenshots/issue-006-media-error.png).

**Воспроизведение:** открыть тестовый товар → Media → Add media → выбрать локальный PNG или JPEG → Save.

### ISSUE-007: Поля аккаунта и оформления заказа не имеют доступных названий

| Поле | Значение |
|---|---|
| Критичность | Высокая |
| Категория | Доступность / формы |
| Адрес | `/dk/account`, регистрация, адреса аккаунта, `/dk/checkout?step=address` |
| Видео | Не требуется: дефект постоянен; приложены снимок и проверка DOM |

**Ожидалось:** программа чтения с экрана сообщает назначение каждого поля («First name», «Address», «Password» и т. д.). Видимый текст должен быть связан с соответствующим `input`.

**Фактически:** у текстовых полей формы входа, регистрации, сохранения адреса и оформления заказа видимые подписи не связаны с `input`. Для полей адреса `input.labels.length = 0`, отсутствуют `aria-label` и `aria-labelledby`, а placeholder содержит только пробел. В дереве доступности они представлены как `textbox "  "`. Поле email названо текстом подсказки `title="Enter a valid email address."`, а не «Email». Это мешает незрячему покупателю понять, какое поле заполнять.

**Воспроизведение:** открыть указанные формы и проверить дерево доступности либо свойства полей. [Снимок оформления заказа](screenshots/issue-007-checkout-unlabeled.png), [выборка DOM без личных значений](evidence/issue-007-checkout-field-labels.json).

### ISSUE-008: Способы доставки объявляются выбранными одновременно

| Поле | Значение |
|---|---|
| Критичность | Средняя |
| Категория | Доступность / переключатели |
| Адрес | `/dk/checkout?step=delivery` |
| Видео | Не требуется: состояние повторяется при загрузке и после выбора |

**Ожидалось:** группа способов доставки содержит один доступный радиопереключатель на вариант; выбранным объявляется только фактически выбранный способ.

**Фактически:** внутри каждого элемента `role="radio"` находится ещё одна кнопка с `role="radio"`. Когда Standard Shipping выбран, внешний переключатель Express Shipping правильно имеет `aria-checked="false"`, но вложенный в него переключатель сообщает `aria-checked="true"`. Оба внутренних переключателя доступны через Tab. Аналогичная вложенная структура наблюдается для Manual Payment. Экранный диктор получает противоречивые состояния и лишние элементы управления.

**Воспроизведение:** на шаге Delivery выбрать Standard Shipping и проверить дерево доступности. [Видимый выбор](screenshots/issue-008-delivery-radios.png), [DOM-состояния радиопереключателей](evidence/issue-008-delivery-radios.json).

| Видео | Не требуется: ошибка видна при раскрытии списка |

**Ожидалось:** список количества содержит каждое доступное значение один раз.

**Фактически:** список показывает 1, 2, …, 10, затем повторно 1. Повторный пункт остаётся после выбора количества 2 и при повторном открытии корзины. [Снимок списка](screenshots/issue-009-cart-quantity.png), [DOM-значения](evidence/issue-009-cart-quantity-options.json).
